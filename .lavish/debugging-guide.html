How to debug this thing

A ladder from cheapest check to most expensive. Climb it in order: each rung tells you which half of the system to stop suspecting, so you never debug the voice pipeline when the problem is a stale build.

The one rule. Nine failures out of ten are one of three things: the agent worker isn't running, you edited webapp/ and forgot .\dev.ps1 ui, or the service worker is serving you an old bundle. Steps 1, 3 and 8 rule out all three in about ninety seconds.

Step by step

1

Ledger tests free no keys 2 sec

.\dev.ps1 test

44 tests over silai/ledger.py: fuzzy name matching, FIFO payment allocation, date resolution, order search, idempotency guards. If these fail, the problem is pure backend logic and nothing above this rung matters.

2

Keys free zero spend

.\dev.ps1 keys

Bounces auth against all three providers without spending anything: Anthropic models.list, Sarvam auth, LiveKit list_rooms. Sarvam is the one you cannot skip - it drives brain, ears and voice. Anthropic only matters if you set BRAIN=claude.

3

Is the page you're looking at actually your code? most common trap

web/ is build output. Editing webapp/src/... changes nothing that FastAPI serves until you rebuild.

.\dev.ps1 ui        # webapp/ -> web/, then reload

To confirm you're running the newest bundle, compare what the page loaded against what is on disk:

# in the browser console
[...document.querySelectorAll('script[src]')].map(s => s.src)

# in the terminal
ls web/assets/

If the hashes differ, you are debugging a ghost. Go to step 8.

While actively working on the UI, skip the rebuild loop entirely:

.\dev.ps1 web       # terminal 1: API on :8080
.\dev.ps1 ui-dev    # terminal 2: Vite HMR on :5173, /api proxied to :8080

Use :5173 for iteration and :8080 to verify what will actually ship.

4

The brain, with no audio in the way cheap

.\dev.ps1 smoke     # scripted Hindi order flow, throwaway DB
.\dev.ps1 chat      # free-form chat in the terminal

Same brain, same tools, same ledger as the voice path - only STT and TTS are removed. If a wrong amount or a wrong due date appears here, it is a silai/prompts.py or silai/tools.py problem and you can stop thinking about voice. There is also a browser version at /debug.html.

smoke sets DB_PATH=data/smoke.db, so it never touches the real ledger.

5

Server and pages

.\dev.ps1 web

Then check the surfaces. /healthz reports which keys are missing without exposing them:

curl localhost:8080/healthz        # {"ok":true,"missing_keys":[]}
curl localhost:8080/api/orders     # ledger read
curl localhost:8080/api/token      # LiveKit JWT - 503 means keys missing

Want data on screen? .\dev.ps1 demo seeds clients and orders. It refuses to run against a non-empty ledger unless you pass --force. Point DB_PATH at a throwaway file first if you care about the real one.

6

Voice without a browser the decisive rung

This is the highest-value tool in the repo and it is easy to forget. silai/probe_participant.py joins the room exactly like the browser would, publishes speech-like audio, and counts audio frames coming back.

# terminal 1
.\dev.ps1 agent

# terminal 2
.venv\Scripts\python -m silai.probe_participant silai-bahi

A pass means the agent joined, heard audio, and spoke back. It splits the world cleanly in half:

  • Probe passes, browser silent - frontend problem. Mic permission, autoplay, or React state.
  • Probe fails - agent worker, Sarvam STT/TTS, or LiveKit. The browser is innocent.

Room name defaults to probe-room if you omit it; the app itself uses silai-bahi.

7

The browser

Both processes must be running - the web server alone is not enough, and a missing agent worker is the single most common cause of "I pressed it and nothing happened".

.\dev.ps1 web       # terminal 1
.\dev.ps1 agent     # terminal 2

Open localhost:8080, press the aura. The caption is your instrument - it is wired to real state, not guesses, so read it literally:

CaptionWhat is actually trueLook at
Connecting… stuck/api/token or the WebRTC connect failedNetwork tab, server terminal
Waking Suhani… then didn't answerRoom joined, no agent arrived within 12sAgent terminal - is it running?
ListeningAgent present and its own state says listeningSpeak; expect Thinking…
Can't hear youLocal mic track missing, muted or endedSite mic permission; a call stealing the mic
Sound is blockedChrome refused autoplayPress Enable sound
Network dropped…LiveKit reconnecting; overrides agent state deliberatelyWi-Fi

Why the states are trustworthy. Network and microphone truth outrank whatever the agent last reported, because no attribute updates arrive while the connection is down - a stale "Listening" would otherwise freeze mid-lie. That logic is describe() in webapp/src/components/VoiceScreen.tsx.

8

When the browser is lying to you service worker

web/sw.js serves /assets/* and /fonts/* cache-first. That is safe in principle - filenames are content-hashed, so new code means a new URL - but a stale index.html can still pin you to an old bundle, and it fails silently on the one device that matters.

Full reset, in order:

  1. DevTools → Application → Service Workers → Unregister
  2. Application → Storage → Clear site data
  3. Hard reload (Ctrl+Shift+R)

Or from the console:

(await navigator.serviceWorker.getRegistrations()).forEach(r => r.unregister());
(await caches.keys()).forEach(k => caches.delete(k));
location.reload();

Also close every other localhost:8080 tab first. Multiple tabs each open their own room session.

9

On her phone

.\dev.ps1 tunnel    # cloudflared HTTPS URL

The microphone requires HTTPS anywhere that isn't localhost, so the tunnel is mandatory for phone testing.

To get a real console from her handset: connect it by USB, enable USB debugging, then open chrome://inspect on the laptop and inspect the tab. You get the full DevTools remotely - and because the build ships .map files, stack traces resolve to real TypeScript, not minified soup.

This is the only way to see the aura at her real device pixel ratio, which is also the only place the shader's resolution behaviour can be judged honestly.

Known traps, already paid for

seen before

Two servers on one port. A system Python and the venv Python both bound :8080 once, and requests landed on whichever won. If behaviour is impossible, check for duplicate processes before anything else.

seen before

Duplicate identity storms. A stale tab retrying with the same identity once killed the agent's publish path with a native panic. /api/token now mints mom-<hex> per connection, but close spare tabs anyway.

by design

Aura looks soft on desktop. The shader's drawing buffer stays at 300×150 and scales with device pixel ratio. At dpr 1 it is upscaled and soft; on her phone (~2.6) it is fine. Do not "fix" it by resizing the canvas externally - iResolution goes stale and the mapping breaks.

by design

Devanagari type rules are load-bearing. The :lang(hi) block in webapp/src/index.css pins line-height: 1.75 and letter-spacing: 0 against Tailwind's Preflight. Remove it and matras clip and conjuncts split.

Still unverified

A live voice conversation has never been run against this frontend. Everything up to the edge is verified - token endpoint returns a valid JWT, all assets serve, the page loads with zero console errors - but the React app has not yet held a real conversation. Step 6 then step 7 is the shortest path to closing that.

The repo is still untracked. git ls-files returns one path: .gitattributes. Every debugging session below is one rm away from being unrecoverable, and there is no diff to consult when something that used to work stops working. This is the cheapest reliability fix available.
