5a · The turn-taking stack - Sarvam-first, model-optional redesigned per your feedback

Your instinct was right: 8M parameters at 93.44% Hindi accuracy cannot own this decision. So no single model owns it - three independent, individually tunable layers do, built almost entirely from Sarvam's own signals:

LayerMechanismWhat it catches
1 · Sarvam VADSaaras's own server-side START/END_SPEECH events (verified live) - the acoustic boundary, ~64ms after silenceWhen she stops making sound
2 · Completeness heuristicsSaaras finals arrive punctuated. Ends in danda "।" or "?" → likely complete, respond after a short wait (~300ms). Ends in a dangling connective ("और", "का", "की", "से", "तक", "तो", "मतलब"...) or no terminal punctuation → likely mid-thought, extend the wait (~1.2-1.5s). A ~30-line rule table for Hindi/Marwari, fully tunable, zero model riskThinking pauses mid-sentence - the exact case where acoustic-only cuts her off
3 · Speculative start with cancelOn a "likely complete" boundary, the brain call starts immediately; if she resumes speaking before Suhani's first audio, the run is aborted and her continued speech merges into the turn. Write tools never execute from a run that gets cancelled - reads may run speculatively, writes only after the turn is confirmedMakes wrong "complete" guesses nearly free: a cancelled LLM call (promo-priced ~₹0) instead of an interruption
4 · Smart Turn v3.1 optional flagRuns as one extra vote behind a feature flag, only if the S2 bake-off shows it reduces false cutoffs on our own Hindi/Marwari clips beyond what layers 1-3 achieveWhatever the rules miss - kept only if measured to help

This is "use Sarvam's own" done safely: Sarvam's VAD and Sarvam's punctuated transcripts drive the decision, Sarvam's brain absorbs the residual errors via speculation, and the third-party model shrinks to a measured, deletable extra.

S2 measured it (2026-08-02): acoustic-only cut off 20/20 pause-trap clips; the layered stack cut off 0/20. Findings that shaped the final tuning: (1) Saaras auto-punctuates dangling fragments ("...लिख दो और" arrives as "...और।"), so punctuation carries no completeness signal - the rule became "complete = verb-final AND not connective-ending" (Hindi is verb-final, so this is linguistically load-bearing); (2) Saaras splits utterances at prosodic gaps, so verb-final FRAGMENTS ("दो काम हैं। ...") fire speculatively - the cancel layer absorbs all of them because the on-device VAD sees her resume within ~150ms (the server's own START events lag by up to 1.1s - local VAD is not optional); (3) winning config: 500ms wait on complete-looking ends, 1800ms on incomplete-looking, cancel window = first-audio time (~1.5s). Cost: ~1 cancelled promo-priced LLM call per trap turn. Smart Turn v3.1 stays OFF - at 0/20 there is nothing left for it to earn.
