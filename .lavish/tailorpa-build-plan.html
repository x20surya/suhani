The stack - chosen for latency and Hindi quality

Every choice below optimizes the same two things: lowest achievable voice-to-voice latency for one user in India, and the most natural Hindi in both directions. Dev cost was not a factor.

Voice framework

LiveKit Agents

Python agent on our VPS + LiveKit Cloud (Mumbai edge) for WebRTC. Chosen over Pipecat because managed media edge handles the messy real world: flaky mobile data, reconnects, NAT/TURN, jitter - exactly what a non-technical user on an Indian network hits. First-party Sarvam plugins and a multilingual semantic turn detector included. Free tier covers one user.

Ears

Saaras v3

Sarvam's streaming STT with the dedicated Hinglish code-mix mode. Trained on 1M+ hours of Indian audio; ~19% WER on IndicVoices, beating global engines on Indic speech. Partials stream at ~200ms. ₹30/hour.

Voice

Bulbul v3

Winner of a 20,000-vote blind test for Hindi naturalness. Streams sentence-by-sentence so she hears the reply while the rest generates. Handles Hinglish + currency amounts natively. ₹30 per 10K characters.

Brain

Claude Sonnet 5

Tool-calling agent loop with adaptive thinking at low effort for the voice path - the best first-token latency at near-Opus tool reliability. Stable, prompt-cached system prefix (0.1x input price). One config line swaps to Opus 5 or Haiku 4.5 if testing says otherwise.

Backend + ledger

Python + SQLite

One Python 3.12 service: the LiveKit agent worker and the ledger live in the same process, so tools are in-process function calls - zero HTTP hop, sub-millisecond. SQLite (one user, zero ops) with Litestream streaming every change to object storage for continuous backup.

Her app

No-build PWA

Plain HTML/JS PWA with the LiveKit JS SDK - no build toolchain, so it ships today and deploys as static files. One big talk button, Devanagari UI, installable from a link to her Android home screen, web push for reminders. Android + home WiFi (your answers) is the PWA happy path.

Deliberately kept swappable: LiveKit makes every component pluggable. If real-device testing disappoints, the fallbacks are pre-researched: OpenAI Realtime (speech-to-speech, sub-second, but foreign-accented Hindi), Gemini Live (~$0.02/min), ElevenLabs Agents (managed, ~$22/mo). The ledger and tools we build work unchanged with all of them.

Instant acknowledgment

Canned Hindi fillers play the moment a tool call starts. A 3-second write feels like talking to someone jotting in a notebook.

Interruption handling

Barge-in built into LiveKit: she speaks, playback cancels in ~100-200ms, generation aborts. Threshold tuned (~300ms sustained speech) so the pressure cooker does not pause the agent.

Measured, not hoped

Per-stage latency instrumentation from day one. We tune against real numbers from her phone and network, and only worry if first-audio exceeds ~2.5s.

The brain: tools and behaviors

Built and tested as a text chat first (days 1-3), then the voice layer wraps it. The agent asks follow-up questions instead of saving blanks, and reads back before every write.

ToolWhat it does
find_clientFuzzy + transliteration-aware match against her client list. STT will mangle names; the ledger never trusts a raw transcript. Names stored in Devanagari with roman aliases.
add_clientNew client, only after find_client misses and she confirms it is a new person
add_orderGarment, client, due date, price, advance taken. Missing fields trigger a follow-up question, not a blank
orders_due"आज / कल / इस हफ़्ते क्या देना है?" - by date range
check_duesWho owes money, how much, since when
mark_paid / update_orderPayments (full/partial), completion, date changes, price corrections
daily_briefingMorning summary: due today, overdue, money pending. Also powers the push notification

Hindi persona, short replies

Warm, respectful, brief - one or two sentences, numbers spoken naturally ("पाँच सौ", not "500.00"). Written for TTS, not for reading.

Confirm before writing

Every ledger write is read back first. This doubles as graceful recovery when STT misheard a name or amount.

Tailoring glossary

Blouse, fall-pico, astar, picot, kurti… seeded into the prompt and matched fuzzily, growing from her real transcripts in week 3.

Prompt-cache discipline

Frozen system prompt and tool list first, volatile context (today's date, session state) after the cache breakpoint. This is what keeps Claude fast and cheap.

Get your keys - your only job today (~30-45 min)

Three services, all self-serve. I create a .env template in the repo with these exact variable names and a matching comment for each; you paste values in. Nothing here needs a company or verification.

1. Anthropic (the brain)

~10 min · needs ~$5 credit
  1. Go to platform.claude.com and sign in (Google works)
  2. Billing: add the minimum credit (~$5 - lasts weeks at our usage)
  3. API Keys → Create Key → name it silai-bahi → copy it immediately (shown once)
  4. Paste into .env as ANTHROPIC_API_KEY=sk-ant-...

2. Sarvam (ears + voice)

~5 min · free credits on signup
  1. Go to dashboard.sarvam.ai → sign up (email or Google)
  2. Open Key Management (dashboard.sarvam.ai/key-management) → create an API key
  3. Paste into .env as SARVAM_API_KEY=...
  4. Signup credits cover all of our testing; no card needed yet

3. LiveKit Cloud (the call itself)

~10 min · free tier, no card
  1. Go to cloud.livekit.io → sign up (GitHub or Google)
  2. Create a project named silai-bahi (pick the India/closest region if asked)
  3. Settings → API Keys → create a key; you get three values
  4. Paste all three into .env: LIVEKIT_URL=wss://...livekit.cloud, LIVEKIT_API_KEY=API..., LIVEKIT_API_SECRET=...

Later this week (not today): hosting

₹0 target

Option A - Oracle Cloud Always Free (₹0/mo): oracle.com/cloud/free → sign up with home region India West (Mumbai); a card is required for identity verification but is not charged. Option B - DigitalOcean Bangalore ($6 ≈ ₹530/mo): zero friction, 5 minutes. Domain: a .in from any registrar (~₹300-800/yr) or a free DuckDNS subdomain to start. VAPID push keys and everything else: I generate, no signups.

Does ₹0 compromise performance? No. The heavy compute (Saaras, Bulbul, Claude, LiveKit media) all runs on those services' own infrastructure - our box only orchestrates audio streams, runs two tiny local models (VAD + turn detection), and reads SQLite. The free Oracle ARM shape is actually the strongest hardware on the table (up to 4 cores / 24GB RAM vs 1 core / 1GB on the ₹530 droplet) and sits in the same Mumbai region, so latency is identical. The real caveats are policy, not speed: free ARM capacity is sometimes waitlisted at signup, and Oracle reclaims idle free VMs - ours is always-on, and switching the account to pay-as-you-go mode (still ₹0 within free limits) removes that policy entirely.
